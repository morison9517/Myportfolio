## 0. 準備するもの(初回だけ)

| ツール | 用途 | 確認コマンド |
| --- | --- | --- |
| Docker Desktop | アプリとDBを動かす箱 | `docker version` |
| Git | ソースコードの共有 | `git --version` |
| VSCode | エディタ(推奨) | — |

**アプリを動かすだけなら、Goを自分のPCに入れる必要はありません。** Dockerの箱の中に入っているものを使います。

> ただし**Goを入れておくと、VSCodeで入力補完と赤線(エラー表示)が効きます。**
> Goは書き間違いをビルド前に教えてくれる言語なので、この恩恵がかなり大きいです。
> <https://go.dev/dl/> から入れて、`go version` が出ればOKです。**5分で終わるので推奨します。**

> Docker Desktop は**起動しておく必要があります**。タスクバーのクジラのアイコンが動いていればOKです。
> PCを再起動すると止まっていることがあるので、`docker` コマンドが失敗したらまずこれを疑ってください。

## 1. 初回セットアップ(1回だけ、10分程度)

### ① リポジトリを持ってくる

```bash
git clone <リポジトリのURL>
cd case_gin
```

### ② 金庫(`.env`)を作る

`.env` は**GitHubに上がっていません**(パスワードが入っているため)。見本をコピーして作ります。

```powershell
# Windows (PowerShell)
Copy-Item .env.example .env
```

```bash
# Mac / Linux
cp .env.example .env
```

**開発中はコピーしたままの値で動きます。**
本番に出すときだけ `SECRET_KEY` と `DB_PASSWORD` を変えます(手順は [DEPLOY.md](DEPLOY.md))。

### ③ 箱を組み立てて起動する

```bash
docker compose up --build
```

初回は部品のダウンロードで**3〜5分**かかります。2回目以降は数秒です。

ログが流れ終わって以下のような行が出たら成功です。

```
web-1  | [起動] http://localhost:8080 で待ち受けます
```

> **DBに表を作るコマンドは不要です。** 起動するたびに自動で用意されます。

### ④ ブラウザで確認

<http://localhost:8080> を開いてください。

- **「セットアップ完了 🎉」と出て、データベースが「接続OK」** → 成功です
- 下のTodoに文字を入れて「追加」できたら、**画面 ↔ サーバー ↔ DB が全部つながっています**
- 「未接続」と出る → DBの起動待ちの可能性があります。10秒待ってページを再読み込み
- 画面が出ない → 下の「困ったとき」へ

## 2. 毎日の操作(これだけ覚えれば作業できます)

### 作業を始めるとき

```bash
docker compose up
```

### 作業を終わるとき

```bash
# 上のターミナルで Ctrl + C を押す。それだけです。
# 完全に片付けたい場合:
docker compose down
```

### コードを直したとき

**何もしなくていいです。** ファイルを保存すれば反映されます。ただし種類によって待ち時間が違います。

| 直したファイル | どうなるか |
| --- | --- |
| `.go` | **数秒待つ**(自動で作り直して再起動)→ ブラウザを再読み込み |
| `.html` / `.css` / `.js` | **待ち時間なし** → ブラウザを再読み込みするだけ |

> **`.go` を保存したときだけ数秒かかる理由**
> Goは「書いた文章を実行前に機械が読める形に翻訳してから動かす」言語です。
> 料理でいうと、材料を切ってから火にかけるようなもので、直したら翻訳し直しが必要になります。
> その翻訳を自動でやってくれるのが `air` という道具で、ログに `building...` と出ている数秒がそれです。

> CSSを直したのに変わらない場合は、**キャッシュ**(ブラウザが前の内容を覚えている状態)です。
> `Ctrl + Shift + R`(Macは `Cmd + Shift + R`)で強制的に読み直せます。

### ログ(エラーの内容)を見たいとき

```bash
docker compose logs -f web
```

**エラーが出たら、まずここを見ます。** `-f` は「流れ続ける」の意味で、止めるときは `Ctrl + C` です。

開発中は**実行されたSQLも全部流れます。** 「思ったデータが取れない」ときに、実際にDBへ何を聞いたのかが見えるので原因が一瞬で分かります。

### 箱の中に入って作業したいとき

```bash
docker compose exec web bash
```

箱の中のターミナルに入ります。出るときは `exit` です。

## 3. データベースの操作

### 表を作る / 増やした表を反映する

**何もしなくていいです。** `internal/models/` にファイルを足して、
`internal/database/database.go` の `Migrate()` に1行足せば、次の起動時に自動で作られます。

```go
func Migrate() error {
	return DB.AutoMigrate(
		&models.Work{},   // ← 足すのはこの1行だけ
	)
}
```

> ⚠️ **この1行を忘れると、表が作られません。** 「保存できない」の原因の定番です。

### 表の形を変えたとき(列の型を変えた)

項目(列)を**増やした**だけなら自動で追従します。
ただし**型を変えた**場合(80文字→200文字など)は追従しないことがあります。一度捨てて作り直します。

```bash
docker compose exec web go run ./cmd/server -reset-db
```

> ⚠️ **中のデータは全部消えます。** 開発中はこれが一番早くて確実です。
> (本番でデータを保ったまま形を変えたいときは、別途マイグレーションの仕組みが要ります)

### DBがどうしてもおかしいとき(最終手段)

```bash
docker compose down -v
docker compose up --build
```

`-v` を付けると**保管庫ごと消える**ので、DBが完全に初期状態に戻ります。

## 3.5 DBeaverでDBの中身を見る

### 接続設定

`docker compose up` でDBが起動している状態で、DBeaverから新しい接続を作ります。

| 項目 | 値 |
| --- | --- |
| ドライバ | MySQL |
| Server Host | `localhost` |
| **Port** | **`3308`** |
| Database | `hack_app` |
| Username | `hack_user` |
| Password | `hack_password` |

> ⚠️ **ポートは 3306 ではなく 3308 です。**
> PCに既にMySQLが入っている人や、Flask版(3307)と同時に動かす場合にぶつからないよう、
> `compose.yml` でずらしています。
> (アプリ側は箱の中で `db:3306` に繋いでいるので、この番号とは無関係です)

### 「Public Key Retrieval is not allowed」と出たら

MySQL 8 のログイン方式のためです。接続設定の **Driver properties** で以下を変更してください。

| プロパティ | 値 |
| --- | --- |
| `allowPublicKeyRetrieval` | `true` |
| `useSSL` | `false` |

開発用のローカルDBなので、これで問題ありません。

### 管理者として入りたいとき

テーブルを直接消したりする場合は、`hack_user` では権限が足りないことがあります。

| Username | Password |
| --- | --- |
| `root` | `root_password` |

### 見ておくと理解が早いところ

- `internal/models/` に書いた設計図が、そのままテーブルの形になっています
- 列を1つ足して再起動すると、テーブルにも列が増えることが目で確認できます

## 4. ライブラリを追加したいとき

例:画像処理のライブラリを使いたくなった場合。

```bash
# 1. 箱の中で追加する
docker compose exec web go get github.com/disintegration/imaging

# 2. 使っていないものを整理する(念のため)
docker compose exec web go mod tidy
```

コードで `import` して保存すれば、あとは `air` が自動で作り直します。

3. **`go.mod` と `go.sum` をコミットしてpushする**

> ⚠️ **これを共有しないと、他のメンバーの環境でビルドが通りません。**
> pull した人は何もしなくてOKです(起動時に自動でダウンロードされます)。

## 5. 困ったとき

### 「画面が出ない / 繋がらない」

```bash
docker compose ps
```

`web` と `db` の両方が `running` になっているか確認します。

- `web` が居ない/落ちている → `docker compose logs web` でエラーを読む
- `db` が `starting` → まだ準備中です。30秒待つ

### 「port is already allocated」と出る

**その番号を別のアプリが既に使っています。**

- `8080` の場合:`compose.yml` の `"8080:8080"` を `"8081:8080"` に変更 → <http://localhost:8081>
- `3308` の場合:`"3308:3306"` を `"3309:3306"` に変更

> **左の数字だけ**を変えてください。右はアプリ側の番号なので変えると動きません。

### 「declared and not used」「imported and not used」と出てビルドが通らない

**Goの仕様です。** 使っていない変数や `import` が1つでもあると、ビルドが止まります。

厳しく見えますが、「書いたつもりで使い忘れている」バグを最初に防いでくれています。
VSCodeに `golang.go` 拡張を入れていれば、**保存時に不要な `import` は自動で消えます。**

### 「テンプレートのエラー」という画面が出た

HTMLの書き間違いです。**画面にファイル名と行番号が出ている**ので、そこを直してください。

よくある原因:

- `{{ if }}` や `{{ range }}` を `{{ end }}` で閉じていない
- `{{ define "content" }}` の名前が `base.html` 側と違う

> 壊れたページだけがこの画面になり、**他の人のページは普通に見られます。**

### 画面に何も出ない / 値が空になる

`{{ .Title }}` のような書き方をしても**渡していない情報は空になります**(エラーにもなりません)。

確認する順番:

1. `internal/handlers/` の `view.Page(c, gin.H{...})` にその項目を書いたか
2. 名前の大文字・小文字が一致しているか(`Title` と `title` は別物)
3. `{{ range }}` の中で全体の情報を使おうとしていないか
   → 中ではドットの意味が変わります。`{{ $.SiteName }}` のように `$` を付けます

### 「整理券(CSRFトークン)が正しくありません」

フォームに**整理券を入れ忘れています**。HTMLのフォームの中に次の1行があるか確認してください。

```html
<input type="hidden" name="csrf_token" value="{{ .CSRFToken }}" />
```

JavaScriptから送っている場合は、`main.js` の `api.post()` を使ってください(整理券が自動で付きます)。

### 「値が届かない / 空っぽになる」

HTMLの `name="○○"` と、Go側の `c.PostForm("○○")` の**文字が一致しているか**を確認してください。ここのズレが原因の8割です。

### DBに保存されない / 画面に出ない

`internal/models/` の項目名が**大文字で始まっているか**を確認してください。

```go
Title string   // ○ 保存される
title string   // × 何も起きない(エラーも出ない)
```

Goでは「小文字で始まる項目は自分のフォルダの外から見えない」というルールがあり、
DBもJSONもHTMLも、その項目を読めなくなります。

### `.go` を保存しても反映されない

```bash
docker compose logs -f web
```

`building...` が出ているか確認してください。

- 出ていない → 保存が箱に届いていません。`docker compose restart web` を試す
- 出たあとに赤いエラー → **ビルドに失敗しています。** そのエラーを直してください
  (このとき古いアプリが動き続けているので、画面は前の状態のままになります)

### それでも分からないとき

以下の3つを控えてから調べ直すと、原因にたどり着きやすくなります。

1. 何をしようとしたか
2. `docker compose logs web` の最後20行
3. ブラウザに出ている画面

## 6. どうしてもDockerが動かない人向け(非常口)

**基本は使わないでください。** Dockerが壊れて時間が無いときだけの手段です。

自分のPCにGoを入れておく必要があります(<https://go.dev/dl/>)。

```powershell
# DBだけDockerで動かす
docker compose up -d db

# .env の DB_HOST を db から 127.0.0.1 に、DB_PORT を 3308 に変更してから
go run ./cmd/server
```

> `DB_HOST` を変える理由:箱の中からは `db` という名前で呼べますが、
> 自分のPCから見るときは「localhost の 3308番」経由になるためです。

> ★このとき、コードを直したら自分で `Ctrl + C` → `go run ./cmd/server` をやり直します
> (自動で作り直してくれる `air` は箱の中にしか入っていないため)。
