# 作品(Products)の書き方

このフォルダの `.md` 1つが作品1件です。トップページ・`/products`・詳細ページ(`/products/ファイル名`)のすべてに出ます。
Go や HTML を触る必要はありません。見本は `Chorus.md`。

> このファイル(README.md)は作品として読み込まれません。

## 作品を1件足す

1. カード用の画像を `web/static/images/products/` に置く
2. このフォルダに `Slug.md` を作る(例:`Chorus.md` → URL は `/products/Chorus`)
3. 下の「設定欄」と「本文」を書く

### ファイル名の注意

- 記号は使わない(`HENRO+` の `+` は共有時に `%2B` に化けるので `HENRO-plus.md` にしている)
- 公開したあとは変えない。変えると、貼られたリンクが404になる
- 大文字・小文字の違いは吸収する(`/products/chorus` は `/products/Chorus` へ移る)

## 反映のしかた

| 環境 | 反映のしかた |
| --- | --- |
| 開発中 | 保存してブラウザを更新するだけ |
| 本番 | 再起動が必要(起動したときに1回だけ読むため) |

書き間違いがあると、本番では**起動が止まり**、どのファイルの何がおかしいかが表示されます(壊れたまま公開されないように)。
開発中は直前の内容のまま表示が続き、ターミナルに `[products]` から始まる行が出ます。

## 設定欄(先頭の `---` から `---` まで)

```yaml
---
name: Chorus                 # 画面に出す作品名(必須)。記号はそのまま書いてよい
date: 2024-03                # 年月(必須)。画面では「2024年3月」。並び順も新しい順にこれで決まる
event: Kloudハッカソン#4      # 参加イベント名。個人で作ったものは「個人開発」
award: デザイン賞             # 受賞。無ければ行ごと消す(バッジが出ない)
image: Chorus-dark.png       # web/static/images/products/ の中のファイル名。無ければ no-image.svg
wide_logo: true              # 横長の透明ロゴ向け。切らずに全体を出し、シルク色の下地を敷く
outline: true                # 画像の端が背景色に近いとき、薄い枠線を付ける
hide_on_top: true            # トップページには出さない(/products には出る)
summary: 1〜2文の概要。       # 題名の下に出る。検索結果やSNSの説明文にもなる(120文字まで)

tech:                        # 使用技術
  - Django                   # 名前だけ → skill.go の同じ名前のスキルのアイコンを使う
  - { name: Spotify, icon: tech/spotify.png }   # skill.go に無いもの → 画像を指定

infra:                       # インフラ。書き方は tech と同じ
  - { name: S3, icon: infra/aws/s3.svg }

members:                     # 共同制作者。url は無くてもよい
  - { name: 名前, url: "https://github.com/..." }

links:                       # リンク(GitHub・発表資料・イベントページなど)
  - { label: GitHub, url: "https://github.com/..." }
---
```

- 要らない項目は行ごと消してよい。`tech` 以下は、空なら見出しごと出ない
- **項目名を書き間違えるとエラーになる**(`wide_logo` を `wideLogo` と書いた、など)。黙って無視されるより気づきやすいため
- アイコンの `icon:` は `web/static/images/` から見た場所。画像がまだ無ければ「?」が出る
  - 使用技術 … `web/static/images/tech/`
  - インフラ … `web/static/images/infra/aws/s3.svg` のように事業者ごとのフォルダ
- GitHub・Speaker Deck・X・YouTube のリンクには、そのサービスのアイコンが自動で付く。ほかは地球のアイコン
- URL は `"` で囲んでおくと安全(`:` や `#` が入っていても崩れない)
- 共同制作者の名前とリンクを載せることは、本人に確認してから

## 本文(2つ目の `---` より下)

ふつうの Markdown で書く。

```markdown
## 大きい見出し(搭載した機能・ハッカソン・感想 など)

### 小さい見出し(Home・Search など)

文章。段落の途中で改行しても、日本語の間に空白は入らない。

段落を分けるときは空行を1行入れる。

- 箇条書き
- 箇条書き

[文中のリンク](https://example.com)   ← 外部のページは新しいタブで開く

![写真の説明(読み上げ用)](Chorus/home.png "写真の下に出る説明文")

![1枚目](Chorus/presentation.jpg "発表") ![2枚目](Chorus/award.jpg "授賞")
```

- 見出しは `##` から使う(`#` を書いても `##` と同じになる。ページの一番大きい見出しは作品名だけにするため)
- **写真は前後に空行を入れて、その行に写真だけを書く**。押すと拡大して見られる
  - 同じ行(同じ段落)に2枚以上並べると、横並びになる(スマホでは縦に並ぶ)
  - `![ここ]` は写真が見えない人向けの説明。**空にしない**。写っているものを書く
  - `"ここ"` は写真の下に出る説明文。要らなければ `"..."` ごと消す
- 写真の置き場所は `web/static/images/products/<ファイル名と同じ名前>/`(例:`web/static/images/products/Chorus/home.png`)
  - **横幅1600px程度まで縮めてから置く**。スマホの写真をそのまま置くと1枚で数MBになり、ページが重くなる
  - ファイル名は半角英数字にしておくと安全
  - イベントの写真に他の参加者の顔が写っているときは、本人の了承をとるか、写らない写真を選ぶ
- HTML タグは書けない(書いても表示されない)
